# 指令维护

先固定用户授权范围。用脚本检查已登记入口、体积预算、已知失效规则和源/安装副本；只报告事实，不把文件数量当作上下文占用。

```bash
python3 <本技能目录>/scripts/instruction_health.py --manifest <本技能目录>/references/targets.json
```

需要去重通知时显式提供 `--state <本地状态文件>`；输出 `notify` 只在问题集合改变或恢复时为 true。脚本不改规则、Git、权限或生产数据。

## 修订

- 跨会话经验只取用户授权可读的完成任务及已脱敏记录，丢弃 reasoning、工具参数、秘密和原始会话数据库。保留来源任务 ID 和日期。
- 优先扩展已有精确技能，避免第二套路由或 Registry。稳定步骤可脚本化，真实风险保留动作前授权。
- 只修改自维护源；第三方插件由插件管理维护。源/安装同步必须有差异审查，不覆盖同文件并发修改。
- 默认流程不能覆盖当前用户要求或现行 ADR。近期状态移到带日期的记录，不放进全局规则。
- 长期记忆只有用户明确授权时更新，写入允许的 memory update notes；不直接改生成的 MEMORY.md/summary。

## 验证

用真实项目重放导致失败的案例：错误运行时、脏文件归属、缺少关键文件、错误 UI 栈、选材漂移。保留实际失败原因；不要只测试文件包含某句话就宣称代理行为通过。

修改脚本后运行附带回归测试；改动语义复杂时可按 skill-creator 的授权条件做独立前向验证。生产、交易、付费或真实数据变更不作为默认回归。
